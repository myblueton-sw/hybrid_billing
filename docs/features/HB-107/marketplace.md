# Source evidence and classification

Initial read-only artifact discovery found one AWS source row with PublisherName `Red Hat Inc.`, InvoiceIssuerName `Amazon Web Services, Inc.` and an explicit Marketplace description, BilledCost USD 0.342 and EffectiveCost USD 0. The authorized artifact partition is 1005 rows with no issuer/publisher difference observed, one candidate row and 115 unknown rows (Google Cloud source-null issuer). A fresh protected database read confirmed this partition and the candidate costs without source writes. Source files do not supply offer/transaction/agreement IDs, seller fees/withheld/net settlement/payout or legal purchase/resale responsibility. Never manufacture them from SKU, charge ordinal, publisher, account or cost difference.

The pinned FOCUS 1.0 marketplace cost use case uses differing non-null InvoiceIssuerName and PublisherName as a reporting signal. Use that exact lexical comparison only as a *Marketplace candidate* in this read-only evidence view, not as proof of a legal transaction or settlement/eligibility. Matching names are 'no issuer/publisher difference observed', not a certified direct-purchase classification. Missing/unmapped/invalid names are unknown. The three disjoint classes partition the selected source rows. A provider label versus a legal publisher name is not a detector. No fuzzy matching, vendor hardcoding, currency conversion or inferred fee/saving.

# Proposed read-only projection

Implement `/api/focus-marketplace` to the existing trusted-local collected-reader HTTP boundary only after independent contract review. The projection runs within existing authorization and protected response delivery. Scope provider/period/account and account-list search `q`; whole-selection aggregates precede bounded pages. No arbitrary raw fields or client tenant authorization. Route accepts existing overview selection keys plus `row` (a selected technical row ID); nonzero offsets/selected row require a derived pinned snapshot and current-page membership. Accounts and candidate rows page at 25. Snapshot binds source, registry/mapping/profile, company and query scope. Search only changes account options; explicit canonical account choice narrows source rows.

Raw allowlist proposal: PublisherName, InvoiceIssuerName, ChargeDescription, ChargeCategory, ChargeClass, ChargeFrequency, SkuId and CommitmentDiscountId. Field states distinguish value, source_null, absent, blank, invalid_type and unmapped_version using per-tenant/batch verified preflight version and pinned null tokens. Only FOCUS 1.0 interpretation is mapped; never upgrade stored versions. Expose bounded candidate charge records with exact Billed/Effective signed scale-18 coefficients and presence counts, currency, canonical account/tenant, service and full charge/billing intervals. Row digests are technical source references, never transaction IDs. Reject overbound source values, malformed queries and stale/off-page selections. No direct raw JSON or secrets.

Candidate totals, counts with no issuer/publisher difference observed and unknown classification totals cover the complete authenticated selection, by currency and cost basis. No rows/all missing is unavailable; known zero is zero. 'Buyer source charges' does not certify customer invoices or paid receivables. Source Credit rows do not prove credit eligibility or original-transaction matching. Seller and benefit counterparts remain unconnected. Global source coverage declarations do not certify selected provider/period completeness.

# Four service views

Buyer charges: focused source controls, candidate count and separate Billed/Effective per-currency totals, paged candidate charge table and selected source evidence. Empty candidate result states 'No candidate rows observed in this selection', not 'no Marketplace purchases'. Do not show generic synthetic fixtures in live mode.

Seller settlement: a compact operational settlement workspace showing distinct gross billed revenue, marketplace fee, refunds, taxes, withholding, net settlement and disbursement concepts as unconnected, without invented numbers or a derived waterfall. Explain that source buyer costs cannot populate seller settlement or prove collection. No fake reconcile/payout action.

Benefits and credits: observed commitment references and charge category remain source context only. Commitment consumption recognition and discount eligibility are distinct unknown contractual decisions. No automatic fee pass-through or invented applied/not-applied status. Credit amounts and original-transaction links require an authoritative counterpart. No activation/approval button.

Mapping: selected source publisher/invoice issuer/account/SKU references, field states and version evidence next to clearly unconnected offer/agreement, legal buyer/seller responsibility and original transaction mapping. No editable pretend mapping or fake saved revision. Account search, row selection, tab navigation, retry/new query and source-detail disclosure are the actual interactions.
