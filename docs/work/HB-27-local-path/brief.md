## Concrete outcome and boundary

A local CLI initializes isolated `hb_local` PostgreSQL/ClickHouse namespaces and an `hb-local-focus` S3 bucket, then accepts a fixture CSV with explicit declared version/source identity, preserves original bytes, first validates the whole file against the server-owned source envelope, quarantines authorized unusable originals under a persistent scope hold, validates consumed fields exactly, loads immutable facts, verifies counts and per-currency/measure controls, records a digest-bound operator confirmation, atomically publishes using stable-scope predecessor CAS and reads a pinned release through a tenant-constrained role. A sealed snapshot exports to Parquet and verifies exact type/controls before rebuild certification. This is executable local scaffolding, not a replacement for the planned Go access API, policy service or React product.

Only labelled synthetic fixtures and synthetic principals are used. The inspected official 1.0 demo remains exploratory and is not relabelled or admitted as supported input. No live connectors, customer data, price approval, deployment or financial issuance. No destructive deletion or automatic stale-writer takeover in this increment: pending/unknown storage operations block the scope until explicit fenced reconciliation is implemented. This supplies fail-closed handling rather than pretending to implement the full lifecycle coordinator.

## Dynamic supported-version contract

A validated JSON registry under `packages/contracts/focus/` owns each supported version's source-to-internal mapping, header requirements, nonnull rules, applicability predicates, allowed enum values, additive/nonadditive aggregation flags, bounded exact product checks and source references. Code uses a generic allowlisted predicate evaluator (all/any/not/equal/in/is_null) and typed fields; no version-specific if/else branches or guessed version ordering. Explicit declared version selects its exact registry entry. Missing/unknown version fails; source header alone cannot infer version. Registry schema validation rejects malformed predicates, missing mapped fields, ambiguous aliases or duplicate internal names, unsafe identifiers and unknown types; no eval or SQL from registry.

Each release pins the canonical selected registry entry digest plus numeric/loader profile and exact original digest. Changing an entry invalidates old confirmations; old sealed readers use pinned immutable release metadata, not today's registry defaults. Supported versions are listed from the registry, not a separate hardcoded list. Future versions need only reviewed registry entries and independent fixtures if their semantics fit existing operators; unsupported new semantics fail until evaluator revision is reviewed. A test adds a test-only version entry and proves dispatch uses it without a code branch.

Intentional source fanout is declared explicitly; a source may feed a legacy field and a canonical alias, but competing producers for one internal field reject.

Local synthetic profile is explicit: Decimal(18,6), max 10,000 rows and 8 MiB input, bounded lexical length/exponent, signed values, four cost measures plus quantity/unit fields. These values are chosen for this local synthetic verification profile only and cannot activate a production/provider profile. Integer coefficient/scale arithmetic validates submitted scale and magnitude before CH; aggregate absolute bounds cover this entire local profile: n*(10^18-1)<10^22, within Decimal128 precision/width. Every local read/export selects exactly one current stable-scope release, so no unbounded multi-release total is enabled. Costs never use binary float, implicit rounding or cross-basis/currency sums. Unit prices are nonadditive: verify them per row and never return a summed unit price. All-missing quantities have NULL coefficients with explicit present/missing counts. The synthetic Compute profile requires an explicit host in versions defining that field; no host-dependent pricing is enabled. Registry-selected nonnull/conditional rules preserve NULL reasons and block invalid input. Narrow synthetic quantity rules must implement the pinned 1.2/1.3 applicability, including 1.3 SkuPriceId behavior, and not claim full FOCUS conformance.

## Storage and consistency

PG migration creates scoped connection/profile, quarantine receipts, releases, attempts/operations, controls, confirmations, publication scopes/decisions, outbox and policy state sufficient for this increment; tenant composite PK/FKs, immutable sealed records, forced RLS and nonowner application role. Local provisioning seeds named synthetic operator/principal scope on the server; CLI offers local persona selection, never arbitrary client tenant SQL. Database admin is used only for local initialization. Runtime commands require current active policy and scope/rights from the seeded principal registry. This local persona mechanism is not product authentication. Every input row must match the server-owned connection capability: exact BillingAccountId, registered SubAccountId and permitted billing/charge period. Provider fields/tags never choose scope. The immutable receipt/source identity includes connection, dataset, exact account scope, period and fixed registered export key; revision CAS stays within it.

CH table is immutable MergeTree with scoped release/attempt/ordinal keys and per-field Nullable Decimal columns. Separate coordinator and tenant-bound SELECT readers; locked candidate settings, no reader mutation/external-function grants. Coordinator-only writes use synchronous inserts tagged with operation identity. Read queries always resolve PG's exact published release/attempt then apply scope+release predicates; no latest selectors. No users share unrestricted reader credentials across scopes.

A PG advisory mutex serializes local coordinator operations, but is not called fencing. Before external mutation a committed pending operation reserves the stable scope; success becomes terminal only after synchronous completion and count/control validation. Exceptions/crash leave unknown/pending and block future mutation/publication for that scope even after lock/session expiry; no automatic retry/load/delete or epoch takeover. This prevents a replacement while the old request might still run. An unresolved quarantine additionally blocks confirmation/publication/query/export after its upload operation becomes terminal; there is no automatic resolution command. Full-file admission is repeated under the reservation lock and current capability is checked again before the quarantine write. Synthetic tests inject failure after insert and prove fail-closed reuse; recovery requiring actual route revocation is deferred and must not be advertised as implemented.

Object writes are immutable conditional creates with SHA-256 verification; original key includes scope/receipt and digest. Release export is addressed by immutable release+digest; unknown writes stay pending, conflicts never overwrite. Source revision ordering is an explicit local integer revision within a fixed source key, not universal provider policy. Same identity/revision/digest is idempotent; same revision/different digest conflicts; newer revision uses expected predecessor scope revision and creates immutable replacement release. Valid equal source rows preserve multiplicity.

Publication requires independently issued confirmation against the exact verified manifest, current operator scope/permission and current active policy revision. Scoped pointer CAS, sealed state, append-only decision and export outbox commit together. Policy withdrawal after confirmation blocks effect. Reader resolves a PG snapshot and holds its scoped read lock/pin through materialization; no deletion exists. Export/disclosure rechecks active policy. A held/unknown attempt cannot publish. Simultaneous same-scope requests serialize and exactly one predecessor CAS can win.
