# Data and interaction boundaries

Read context for the exact selected contract and explicit list date. A historical contract selection still uses the current billing profile, as the server declares. Display both bases; never silently substitute today's date. Keep lifecycle sequence, contract revision and billing revision distinct, preserving their uint64 wire values as strings rather than rounded JavaScript numbers.

Read retained configuration history independently of current context availability. History may remain readable after current source changes; a failed context must not silently erase that distinction. History does not establish current permission or eligibility. Unknown proposal/confirmation states remain uncertain even when a module observation is active. Do not adopt legacy records into public mutations.

New proposal IDs are generated internally. Freeze target, selected date, source digest, document settings, rationale and command envelope before submission. Retain unresolved attempts at session scope across contract/tab navigation, reject late reads from previous scopes, and preserve exact retry identity. Fresh recovery must use the original actor and immutable retained business identity. Independent confirmation must show the exact retained settings and original proposer before sending.

# Option-source gap

The current implementation accepts only erp_issuance with synthetic_erp_document_v1. The profile validator checks uppercase two-letter region syntax, a request-ID-shaped tax reference and an IANA timezone; this does not establish a discoverable jurisdiction/tax catalog or statutory applicability. A text box requesting an unexplained tax identifier would not satisfy the operator plan. Discovery must establish an existing named supported source or define a truthful synthetic-only option contract before the proposal form supplies choices. Do not invent legal tax options, derive jurisdiction from locale, or silently default the document timezone from contract presentation metadata.
