# Independent temporal and subject findings

The protected module measures channel age from admission to the change's request instant. Waiting until verification cannot repair a too-early request. Issuance resolves distinct exact subjects entity:<entity>, customer:<customer> and kind:<kind>; a mature customer channel cannot verify a kind-owned template change.

Independent investigation therefore requires channel ownership before financial-profile binding. Customer/entity channel subjects must derive from authoritative organization records with retained organization evidence. Kind channels need a separately governed prospective kind reservation that fixes the explicit immutable profile specification and deterministic future kind ID before current final approval. Such a reservation must not invent a module kind or grant issuance eligibility. Later source-bound profile creation must consume the exact reservation, retain current-source checks and continue refusing existing foreign kinds. This reservation contract is still to be specified and independently reviewed before channel integration.

The required fixture sequence is T0 actual organizations, explicit rules and prospective kind reservation; actual channel registration and independent admission for each exact subject; monotonic shared-clock advance beyond the configured24h before requesting changes; fresh sessions and newly governed rights; then current charge/result/final/profile evidence at T1, protected request, independent verification and fifth-actor approval. No backdated admission or reduced lifetime rule is permitted.

# Proposed prospective-kind contract for the next step

Before channel integration, add an at-most100-entry service-owned reservation map keyed by the future profile Spec.ID. A reservation retains workspace, the complete already-closed synthetic ERP profile spec, deterministic future Kind, proposer/rationale, independent confirmer and an immutable intent digest. No source, module Kind, protected reference, invoice, number or permission is created by reserving it. Two actual current installation governors propose/confirm this configuration; the original proposer and confirmer must remain eligible when the reservation is later consumed. No existing unowned module kind may be reserved or adopted.

Reservation publication is an in-memory configuration operation, so use proposed/confirmed states with before/after-publication failure injection, not a fictitious module-write phase. Exact same-owner retries return only current matching intent. Competing specs under the same future ID refuse. A channel for kind:<id> may later derive that subject only from this confirmed owned reservation; it must not accept a caller-selected kind identifier.

Source-bound profile creation must require and consume that exact confirmed reservation. Preserve current final/source checks and the existing profile governance/unknown recovery. Bind reservation consumption to the resulting exact profile digest together with the existing profile/economic-scope ownership, before Define. A before-register fault leaves consumption untouched. An after-module failure retains both reservation consumption and the original unknown profile, preventing another source or profile ID from taking the reserved kind. Reservation replay after consumption must validate the exact owned profile association and module kind rather than treat the now-present kind as foreign or adopt it without evidence. No automatic release or reassignment is allowed.

Existing synthetic profile fixtures must perform actual reservation governance before profile creation; do not leave a production creation bypass merely to preserve tests. Fixtures not testing maturity can reserve at their current time. The future channel test must reserve and admit atT0, then create fresh final evidence/profile atT1 after actual clock advancement. Tests must establish no module kind before consumption, closed spec/current governors, foreign-kind refusal, tampered/wrong reservation refusal, cross-source reuse refusal, before/after profile publication recovery and unchanged independent profile behavior. The independent review outcome and binding requirements follow; this contract is not implemented by the authority/rules checkpoint.
