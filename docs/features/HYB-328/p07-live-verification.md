# Implemented scope

P07 uses the existing authenticated service context for GET /licenses and initialize, select_mode, register and activate commands. The page shows only strictly parsed server facts: installation identity, current mode/status/reason, authority configuration, last verified evidence, entitlement channel/metric/scope and evaluation references/bounds. Provider configuration is not verification. Remaining seconds are shown only for evaluation active/expired; zero truncated whole seconds does not override the producer's active state. There is no client clock countdown or expiry access gate.

An uninitialized configured installation offers explicit initialization with a reason. Usage mode is an unselected radio choice, distinct from the saved server mode; saving is a declaration and grants no rights. Offline submission accepts a JSON file of at most 12000 bytes with canonical standard-base64 body (1–4096 decoded bytes), signature (64 decoded bytes) and optional exact terms reference. The browser preserves signed bytes, splitting only the transport encoding at 4096 characters. Unknown fields, invalid encoding, controls and invalid terms are rejected. Terms use the domain's 200-byte UTF-8 bound, including permitted exact surrounding spaces. The UI never presents the reference as the missing terms text. Evaluation requires an unchecked express consent control; replacing the file resets consent. Commercial registration and evaluation activation are different domain commands. No envelope or terms are stored in browser storage or URLs.

Every read clears previous facts before loading. Denial, malformed responses, missing authority and storage failures remain distinct from empty inventories and active rights. Session/workspace/CSRF replacement remounts the scoped component and discards late responses and input. A session-object-keyed controller acquires its pending lock synchronously before dispatch, preventing duplicate submission across remounts. Only request/result diagnostics and pending state are retained; submitted files, reasons and consent are not retained. Settlement updates the original session even after navigation, and a settlement generation triggers a fresh read in the current view. Each new attempt replaces old result diagnostics. Completed request identity/outcome survives a later status-read failure. Transport failure, malformed command success and uncertain operation responses lock further mutation in the current in-memory login session, including refresh, tab, locale and notice-view changes. Inspection is required; the local latch is not a durable operation-reconciliation service across full browser reloads.

Notices remain independently accessible when installation administration is refused. Support and Marketplace data remain unavailable; key administration remains API-only. Existing P07 routes, shell and owner review controls are retained. Stable items are recorded in the plan; no owner FIX is created.

# Design and terminology

The actual Claude CLI ui-designer invocation read the existing notice renders and issued implementation guidance. Adopted the full-width existing ops-grid, neutral state blocks, semantic facts, separated forms, bounded controls and visible focus. Consulted [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/) for labelled facts and [Error summary](https://design-system.service.gov.uk/components/error-summary/) for focus and field links; rejected decorative red edges and a fixed page-width container. No upstream assets, styles or dependencies were copied.

Root reconciled design suggestions with the actual contract: terms are references, not supplied text; activate consumes the evaluation grant directly; unknown enums fail parsing rather than being interpreted; the envelope uses a standard browser file input. The native file-picker button follows browser language, while the product label/help are EN/KO/AR. Existing English shell spelling and Arabic tab wording are unchanged; native-language acceptance remains pending. The final Claude CLI visual re-review passed on nine assigned renders after the three blockers were corrected: checkbox geometry, actionable error text and retained unknown-result diagnostics. The reviewer did not execute browser tests and did not certify native-language acceptance. A nonblocking paragraph-spacing cascade finding was corrected with scoped specificity and computed-margin/render checks. Independent code/technical-writing review passed after correcting current-request diagnostics, valid subsecond evaluation, strict calendar/interval/scope checks, exact terms and localized refusal explanations.
