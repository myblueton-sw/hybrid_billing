# Proposed data contract

Keep `/api/focus-receipts` and its closed v1 DTO unchanged. Add fixed-reader GET `/api/focus-collection-status` with no accepted query parameters and the existing host/origin/header/body, concurrency, error and response-size guards. Use `collection.query(...,limit=1,_consumer=...)` so authorized slices, physical controls, archive behavior and hierarchy checks remain authoritative; no initialization/repair/put/import. No account/resource/source body, whole-file identity/hash/bytes, foreign counts, financial amounts or raw tenant/window/batch IDs may enter the DTO.

A preflight under the same query guard/transaction calls the existing receipt projector with imports/default selection solely to obtain its exact audience/member count/auth_scope/permission_revision. Do not reimplement weaker permission pins. From successfully verified permitted rows derive row_count, distinct contributing delivery count, contributing source versions, provider row counts, source windows and allowlisted provenance counts (official-public, official-public-subset, synthetic-contract-fixture, unclassified). A zero-row authorized slice cannot contribute a delivery, version or period; foreign-only delivery existence stays hidden. Period row counts count authorized rows only, including mixed-origin originals without exposing their complete metadata. Include current UTC observation time and a projection-specific stable snapshot, read_only true, financial_authority false, source_classification exploratory-query-only, upstream_completeness unverified and original_availability not-checked. Bound providers/periods and total response. Empty authorized results are exact0; read failure is unavailable, not0. A company-scoped period is neither a complete original-file receipt nor evidence of whole-provider completeness.

Frontend reads source status only after a valid receipt response. Bind each read to the receipt request identity and cancel/reject late results. Require exact audience/member count/auth_scope/permission_revision equality before presenting both observations together; mismatch clears receipt/selection and requires explicit refresh. Ordinary source availability failure clears source counts but preserves still-valid receipt metadata with distinct failure/retry. Any HTTP403, revoked/denied authority or pin mismatch clears receipt, selection and source together and requires explicit refresh. Refresh, tab, filter, locale and scope changes invalidate source observations. No shared cache or local authority is introduced. Source counts describe all current permitted rows and do not follow the receipt-prefix search; label this explicitly. Each observation keeps its own timestamp/snapshot. Never expose the collection.query source snapshot: it includes whole-delivery private metadata and stays internal. The public status snapshot hashes only the allowlisted DTO projection excluding observed_at and snapshot, not raw source rows, identities or foreign metadata. Existing tabs/search/paging/detail/review controls remain functional.

# Closed status DTO and invariants

Exact top-level keys: schema (integer1), profile (retained-focus-collection-status-v1), read_only (true), financial_authority (false), audience (company|tenant), member_count (integer1..10000), auth_scope and permission_revision (the unchanged receipt projector's SHA256 pins), snapshot (SHA256 of the complete allowlisted DTO excluding observed_at/snapshot), observed_at (valid UTC ISO timestamp), row_count (integer0..10000), delivery_count (integer0..row_count), versions (unique sorted supported version strings, max128, pattern digits1-2.digits1-2), provenance (exact four keys official-public/official-public-subset/synthetic-contract-fixture/unclassified, each integer0..10000), providers (max128), periods (max120), upstream_completeness (unverified), source_classification (exploratory-query-only), original_availability (not-checked). Response cap2MiB. No other fields.

Each provider is exactly {provider: nonempty string max256, row_count: integer1..10000}; unique names in ascending order. Each period is exactly {window_start: UTC ISO, window_end: UTC ISO, row_count: integer1..10000}; start<end. Group periods by canonical [start,end], merging permitted rows across contributing deliveries/connections with the same interval; unique ascending(start,end). Source windows are not charge months. Provider counts, period counts and provenance counts each sum exactly to row_count. All count/version/provider/period outputs derive from successfully verified authorized rows; row_count0 requires delivery_count0, versions/providers/periods empty and all provenance counts0. Public summary hash remains unchanged when only foreign-only delivery metadata changes. No public source_snapshot.
