# Evidence and query boundaries

At the7abd8a5 baseline, listServices downloaded all service accounts, all credentials for each and all eligible owners; openPickups scanned all pickup records. These are historical pre-migration observations, not the current M04 handler. Known service/credential commands now have direct module lookups, and declarations have an actual producer. At that baseline, indexed ServiceUsers/CredentialPage/PartyPage/catalog pages existed, while Members filled pages by skipping removed entries and did not bound scanned positions. Subjects.Generation did not change for credential writes. Organization and contract-lifecycle registries lacked workspace query generations, and secret collection changed delivery state outside the ordinary command revision. The implementation described below adds dedicated bounded positions/fences and delivery indexing without changing those original domain-generation semantics.

The M04 spec requires canonical selection, account/purpose/responsible owner/audience/scope/expiry fields, organization/owner/scope/expiry/state filters, independent account/credential views, stable snapshots and bounded browser populations. These requirements include the global never-collected reminder and service selectors; paging only the account table would lose HYB-333 recovery information. Existing account admission200 is not an excuse to download every credential or configured owner population. Identity credential limits are positive configuration values without a small fixed protocol ceiling, so a single service can exceed one request's work budget.

Choose signed continuation plus source fences over retained whole-list snapshots. No query allocates a browser-wide result array or a server snapshot copy. Fixed reference time governs query predicates; current authority is checked separately on every request. Changes to the fenced source require an explicit refresh, without silently replaying an old query over a different population.

# Inputs, rows and counts

Reject malformed query encoding, unknown keys, repeated/empty values, foreign workspace selectors, invalid IDs and overlong input before source/count disclosure. Raw query bound8192 bytes; search uses the existing canonical bounded search parser and rejects controls. The normalized query is returned so the browser can show applied filters/chips and browser history accurately. Counts, reference time and order identify the same filtered scope.

Account query: q across canonical account ID, declared purpose and recorded responsible-owner label; organization and owner canonical IDs; audience/scope paired references; expiry all/none/expired/expiring/valid; state all/active/suspended/retired; declaration all/recorded/missing. Recorded means a stored declaration exists, independently of current eligibility; it is not an eligible-access filter. Scope requires its audience to avoid ambiguous repeated scope IDs. Missing declaration can match missing but never a fabricated empty purpose/organization/allowlist. Expiring means at least one unrevoked credential ends after reference and within the configured warning days; expired means at least one unrevoked credential has ended; valid means at least one unrevoked unexpired credential. None means no recorded credentials. These filters do not change credential validity or confer request authentication. Preserve existing active-capacity treatment of future-start unrevoked credentials; current usability remains separate from capacity.

Account rows carry canonical identity/state/epoch/owner/creator labels, declaration state/version/purpose/organization and bounded selected audience/scope IDs, plus credential aggregates and earliest unexpired expiry. They contain no credential rows or full catalog. Recent use remains unavailable because the actual service-request authentication/use producer is absent. Configured recipient/scope metadata is not effective permission.

Credential query: q over canonical credential/service IDs; optional exact service; state all/active/expired/revoked; collection all/uncollected. Stable order is service ID then credential ID. Account and credential view queries/cursors/selection are independent. Uncollected means an active-at-reference credential with a recorded delivery whose secret was not returned; it includes open and never-collected current recovery annotations. Unknown delivery metadata is unavailable, not uncollected or stored. Existing collected means returned once, never confirmed safely stored.

Every list returns rows, normalized query, next, reference_at, order, scan_stopped, charged work_units and count with exact/lower_bound certainty and effective setting rows. Count is cumulative matches through the signed continuation; exact is asserted only at end of source. An empty scan-limited page with next is not a complete empty result. Decimal-string count values avoid browser integer rounding; server accumulation is checked before overflow. Workspace account admission count is a separate exact indexed count, not the filtered result count. Do not eager-scan the whole source merely to display a header total.

# Bounded nested scans

An enumerated list request charges one unit for each examined service, credential, member-position, party or audience entry. Reserve eight units before fetching/evaluating one scope entry: its catalog read, at most two named selector-party checks, contract metadata lookup, indexed lifecycle position, narrow contract-party read and at most two contract-party eligibility checks. The work_units response reports conservative charged units rather than claiming every reserved exact operation happened. Unused reservation stays charged conservatively; if eight units do not remain, pause before that scope without advancing its position or marking it ineligible. Limit both output rows and total examined positions. Fetch at most the remaining budget from module indexes, without hidden population filling, sorting or map copies. Account aggregate filters may need all credentials of a candidate; pause instead of violating the budget.

The signed account continuation stores the last completed service, optional pending service/last credential and bounded aggregate accumulator (counts/earliest expiry/expiry flags), plus cumulative matched count. Complete that service before emitting its account row or advancing the completed boundary. A changed source invalidates partial aggregates. Credential query similarly stores current service/credential positions. No credential population or secret is stored in a continuation. Empty budget-limited responses return explicit progress/next; the UI offers continuation without interpreting zero returned rows as no matches.

Named-contract scope validation uses a new authoritative current-revision timeline index, not StateOn→Lifecycle/holding. Amend already prepares a sorted validated active timeline; prepare its date/Position prefix index before committing any mutation, store it atomically with that accepted timeline, and binary-search it under the registry lock through CurrentPosition(workspace,id,day). Return the current sequence with the Position in that same read. Withdrawal, replacement and future scheduled events update the index; rejected/replayed writes leave it unchanged. Historical StateOn(at sequence) and settlement behavior remain unchanged. Verify the new current index against an independent lifecycle/state oracle across amendments, withdrawals, equal date boundaries, future transitions and replay; do not reuse the implementation's index builder as the oracle.

Add organizations.ContractParties(workspace,id,revision) as an exact narrow read of recorded customer/seller IDs without copying the revision's potentially large Components population. It shares ContractRevision's canonical lookup semantics, not new eligibility or grant policy. Exact party eligibility performs a constant workspace/party/parent lookup; the scope reservation covers all such calls. Scope field/restriction projection is separately bounded by the existing complete catalog's1MiB normalized metadata ceiling and the page limit; configured recipient size2048 and field representation bounds are preserved. No event/component population work is hidden behind a charged scope entry.

Known-ID detail does no enumerated population scan. Its separate derived work bound is the configured declaration-scope count (protocol maximum64), each requiring at most eight exact/indexed operations, plus constant owner/organization/service checks; history is bounded by the configured version count (protocol maximum20). It never calls an unbounded event/component/owner/credential read to obtain those values. The list scan setting governs list enumeration, not an implied smaller hidden allowance for this explicitly bounded exact-detail contract.

Owner module scanning returns at most the requested number of index positions, last scanned ID and whether positions remain, even when removed memberships produce no row. Current administrator authorization is checked at actual request time. Candidate role From/Until is evaluated at the signed reference, separately from a known-ID current eligibility read. Party/catalog scans use their existing sorted bounded indexes, then exact eligible reference checks. Organization labels currently come from the actual orgNames producer; a missing label is explicitly unavailable with canonical-ID fallback, never synthesized from an ID or creator. An audience's configured scope count is not an eligible scope count; determining eligible entries requires its own bounded scope query.

# Sources, time and cursor integrity

Add narrowly scoped module query fences rather than hashing/downloading populations:

- Identity service basis uses a dedicated saturating subject-query generation plus a per-workspace credential mutation generation. The existing15 subject-mutation notifications preserve their original Subjects.Generation increment through one helper while also notifying the new query counter; putUser/putMembership notify only the query counter additionally. Original permission-cache/domain generation behavior is preserved, while the new query counter remains sticky-unavailable even if the original eventually wraps. Credential insertion, pruning/removal and revocation advance the latter, including serial-reuse cases. Direct known reads and page reads reauthorize. The original generation cannot be reused alone.
- Organizations expose a workspace query generation advanced by successful workspace/party/profile/contract-revision writers; failed writes leave it unchanged. Lifecycle exposes a workspace generation advanced at its shared successful record commit. Conservative invalidation within the same workspace is acceptable; do not disclose another workspace's activity through a public counter.
- Server basis includes global command revision, immutable catalog fingerprint, directory label version and delivery version. Check applicable module bases before and after bounded projection to reject concurrent direct-module changes as a changed view. No mixed-generation page is returned.
- Delivery writes use centralized insertion/removal helpers and a direct credential-to-pickup lookup, plus delivery generation. Issue, collection, expiry pruning, session-targeted removal, revocation and forgetting update these indexes consistently. Reads do not expose pickup references or the backing secret. Avoid openPickups/global pickup scans in the new list path.

New query-generation counters saturate instead of wrapping. An exhausted fence makes the dependent query basis unavailable; it cannot reuse an earlier signed view. Existing domain mutation policy is not changed merely to maintain a query counter. Test this defensive boundary explicitly.

Source bases are represented by a process-keyed opaque fingerprint in public continuations, not raw module generation counters. Coarse identity changes can still invalidate another workspace's query and require refresh; opacity hides ordinal counters, not all activity-related refresh observations.

Every cursor has an authenticated area/version, current canonical user/workspace/epoch and exact caller handle, normalized-query digest, source bases, positions/accumulators, reference and fixed expiry. Use a dedicated random process key/domain; reject cross-route, cross-query, cross-user/session/workspace, tampered, malformed, expired, changed-source and prior-process continuations uniformly as an explicit view-change/refresh result. Bound cursor bytes and fields; never accept a caller-supplied reference/accumulator without its signature. Continuation cannot extend the original lifetime. New successful writes must not silently replace a held attempt's fingerprint or confirmation.

Reference time freezes every list-membership time predicate, including credential expiry, owner role periods and named-contract lifecycle eligibility in scope choices. Scope list checks call the indexed current timeline at the signed reference day; a scheduled start/suspension crossing midnight cannot change a continuation without a writer. Known-ID eligibility and command execution use the actual current day instead. Recorded/missing declaration filtering tests record presence only and never substitutes for eligibility. Current caller authority is rechecked on every read, including natural role/session expiry. Known service/credential/owner/scope details and every command recompute current eligibility. Credential pickup open/never annotations are live observations with observed_at, not frozen list-membership predicates; the collection filter uses the fenced recorded returned/not-returned state. Live open availability belongs to the original issuing session; another administrator seeing open is not promised collection rights. Thus original-session loss or expiry can truthfully change a pickup annotation without silently changing a signed set's collection predicate. The UI distinguishes loaded/reference time from observed pickup availability and never promises a secret is still recoverable from a list estimate.
