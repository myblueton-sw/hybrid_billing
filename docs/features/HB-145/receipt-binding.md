Claude CLI supplies material data-layout composition and compares real renders. The branch stacks on de12d913d786efbb0c898bc854ea0626ffb47107, not fresh main; no merge/deployment is claimed.

The first next vertical slice is default S03 `/imports`: inspect actual retained collection deliveries, attributable quarantine, registered completeness expectations and receipt detail using real protected reads. No upload, reimport/reset, migration, confirmation, publication, financial operation, customer data or real-account use is introduced.

# Actual producer and guard

Reuse the existing GET-only OverviewServer and fixed server reader actor, `collection.access(actor, 'query')` plus `c.a.transaction('query')`. Preserve exact Host/Origin/FetchSite/custom-header validation, concurrency limits, sanitized error/request IDs and no-store. This is a trusted local operator interface, not public multi-user authentication. Do not call lifecycle/operator whole-journal projections, `collection.query` warehouse/original-row loading or mutate receipts as part of inspection.

Only completely authorized delivery/receipt/connection domains enter the projection. Explicit connection ownership requires all registered domains to resolve through current verified source configuration/active tenant bindings and be a subset of current permitted members. Legacy successful delivery ownership requires the exact manifest/descriptor and all actual affected tenants; neither an intersection nor zero-row placeholder slices prove full ownership. Ambiguous or unresolved ownership fails closed; no all-tenant fallback. Unadmitted rejected receipts have no tenant ownership and are excluded entirely, including counts and search. Never return global rows/bytes/hash for a mixed-tenant artifact unless all affected domains are currently permitted. Quarantine lineage references are returned only if independently attributable to the same authorized scope; otherwise null. Do not serialize raw journal, object keys/URLs/paths/filenames/bodies, configuration, plans, holds, credentials or full batch tenant-slice maps.

Collection `registered`/`verified`/`sealed` are past collection stages, not job-success or billing-readiness evidence. Initial lineage receipt time is labelled accordingly, not per-revision arrival. Completeness is at most the operator-registered calendar/domain expectation with upstream verification false. Explicit published zero-domain attestations alone can establish known zero. No persisted duplicate counter or OCR/verifier producer exists; these stay unknown/unconnected. Metadata does not establish current physical object/warehouse presence or financial eligibility.

# Closed consumer contract

Implemented fixed GET `/api/focus-receipts` accepts only view=imports|quarantine|completeness|extraction, bounded optional q, after and snapshot/permission_revision pins. No actor, tenant, company, arbitrary URL, body or command input. Query matches only currently authorized projected metadata. Bounded pages contain at most25 records; after>0 requires exact current snapshot and permission revision. Changed evidence/permission causes reload rather than silently rebasing a page. No hidden full-result browser population or global cross-tenant hash.

Envelope keys: schema=1, profile='retained-focus-receipts-v1', read_only=true, financial_authority=false, commands='unconnected', view, selection={q,after}, audience, member_count, auth_scope, permission_revision, snapshot, observed_at, total, next_after, capabilities and records. Hashes are lowercase SHA256. Audience is tenant/company from the fixed actor gate; member_count is only that actor's current authorized membership count. total is an exact permitted-projection count or null when unsupported, never an inferred zero. Capabilities: receipts='fully-authorized-metadata-only', completeness='registered-expectations-only'|'unavailable', extraction='unconnected'. Extraction returns total=null and no fabricated records. Snapshot binds projection version, current authorized actor/membership and relevant authorized policy/config evidence, selection and only permitted facts; exclude volatile observed_at and unauthorized activity. Never expose or hash the raw global control head, sequence, digest, whole journal or whole configuration into public pins. Internal integrity checks may use them. Only authorized canonical facts/current memberships/relevant policies affect public snapshot and permission pins. The snapshot covers every returned record value, capability, count and selection; a changed value invalidates screen review.

Every record has the exact keys: id, kind, connection, stage, window_start, window_end, source_revision, focus_version, format, declared_rows, file_bytes, file_digest, mapping_digest, received_at, complete_through, finalized, reason, root_receipt, replaced_by, attempts, known_zero, published. Kind is delivery/quarantine/coverage. IDs are canonical opaque SHA256 references (coverage may use a deterministic scoped reference); linkage remains canonical. Optional metadata uses null, not omitted fields. Count/revision values are bounded decimal strings rather than JavaScript numbers: declared_rows0..10000, file_bytes0..16777216, source_revision1..2^63-1 and attempts0..10. Unsupported per-kind values are null. total/after/next_after are safe integers0..10000 (total may be null); exceeding this explicit local inspection window rejects rather than truncating/claiming complete coverage. member_count is positive and bounded by the actual authorized membership set. next_after requires a full25-row page and exact remaining records. Dates are valid ISO UTC intervals with end exclusive. Strings are bounded; reasons are safe machine codes, not arbitrary exception/source messages. Delivery stages are registered/verified/sealed; quarantine stages quarantined/replacement-requested/escalated/resolved/deleted; coverage stages registered/verified/sealed/quarantined/replacement-requested/escalated/missing/late. Rejected receipts are unowned and excluded. Delivery received_at is the window lineage origin; quarantine received_at is that receipt timestamp; coverage received_at is null. Coverage published is an explicit boolean independent of latest stage (null outside coverage). complete_through/finalized/known_zero come only from the current published descriptor, never latest unpublished/quarantine evidence. attempts is an attributable root-lineage counter, not a child default or duplicate count. IDs/digests are SHA256; connection is a nullable producer token up to64 characters; format csv/parquet/null; focus_version is a bounded actual registry token; safe reason matches lowercase letter followed by up to79 lowercase letters/digits/underscores. Unsupported or contradictory records are rejected. No fields are invented to populate nulls.

Delivery and quarantine require their producer-supplied period, revision, declared rows, source version, file hash and receive time; delivery additionally requires the mapping hash, while admitted quarantine requires connection and reason. Unsupported fields must be null. Admitted descriptor/file-hash/version contradictions fail closed. Published coverage requires current complete-through and explicit finalized/known-zero booleans; unpublished coverage must leave these null.

Backend response bytes and client streamed bytes are bounded (maximum2MiB); fatal UTF8 decoding, JSON/closed key/type/duplicate-ID/status validation, redirect rejection and no-store are required. Errors use closed safe code/request ID fields. The frontend issues GET only, fixes endpoint and query keys, aborts obsolete requests and uses a monotonic sequence plus synchronous identity masking. Selection belongs to the current page/snapshot; scope/filter/view/permission/error clears it. Retry refresh never issues a mutation.

# Required portability correction

Backend implementation exposed an inherited top-level Unix-only fcntl dependency in the control lock. Root owns a minimal native adapter and control.locked delegation outside the backend writer scope. POSIX retains the exact same sidecar inode/path and flock LOCK_EX/LOCK_UN so running prior readers remain mutually exclusive. Windows lazily uses msvcrt.locking at offset0, length1, on a binary nontruncating handle. Byte-range locks may extend beyond EOF; no initialization write is needed. Entry occurs only after acquisition, release follows body exceptions and handles close after acquisition/release failures. Unknown platform/import/locking failures fail closed. No in-process-only replacement or reentrant bypass is introduced.

[Python msvcrt](https://docs.python.org/3/library/msvcrt.html) specifies up to10 one-second acquisition retries before OSError; Windows contention may therefore produce a safe service-unavailable response rather than identical indefinite POSIX waiting. [fcntl](https://docs.python.org/3/library/fcntl.html) remains a POSIX adapter only. Local filesystem coordination is the target; cross-OS shared filesystem lock interoperability is not certified.

Actual POSIX process/thread/old-reader interoperation and exception-release tests use temporary paths. Windows tests emulate the API contract and do not establish native Windows startup, concurrency or filesystem behavior. The inherited durable(write) directory-fsync path remains a known write-path portability gap; it is not invoked or weakened by this read-only slice. Full installation/write durability and other-OS execution are not claimed complete.
