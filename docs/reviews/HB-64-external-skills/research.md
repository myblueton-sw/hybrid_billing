# Recommendation

Use a small, task-scoped set of external references alongside the existing project skills. Prioritize Vercel React performance and composition guidance, an adapted web-interface checklist, and Microsoft Playwright browser/test guidance. Treat Vite and Vitest references as conditional on the actual toolchain and locked versions. Add accessibility guidance backed by W3C patterns. Do not install a complete marketplace bundle or replace the repository workflow.

This is a recommendation, not an installation or an implementation acceptance. The owner's renewed research request precedes actual React implementation. No candidate script, installer, external model, cloud deployment or browser-profile action was executed. No third-party skill was installed, activated or copied into the project's discovery directories.

Downloaded source snapshots are temporary research evidence outside the repository and are not installed skills. Remote content was treated as evidence, including instructions that ask an agent to run code or change its workflow. Candidate instructions were not followed as active task instructions.

# Project fit

The [owner decisions](../../architecture/current-design-decisions.md) select React frontend, Go backend and Python processing. This survey does not select Next.js, Vite, a UI kit, cloud hosting or new data engines. [Planning completion](../../planning/planning-completion.md) supersedes historical planning-gate wording in earlier design documents.

The [HB-63 design rules](https://github.com/myblueton-sw/hybrid_billing/blob/4d51763458b314fd766998c05fb32a1c40c99e72/docs/design-system.md) preserve supplied SVGs, local IBM Plex fonts, semantic tokens, square geometry and EN/KO/AR behavior. The [OS rule](https://github.com/myblueton-sw/hybrid_billing/blob/4d51763458b314fd766998c05fb32a1c40c99e72/.agents/rules/platform-independence.md) covers installation and operation; an optional developer helper or Linux container is not a universal product support guarantee. [Screen acceptance](https://github.com/myblueton-sw/hybrid_billing/blob/4d51763458b314fd766998c05fb32a1c40c99e72/.agents/rules/screen-review.md) stays owner-controlled and revision/scope-bound.

Existing local pm, planner, architect, dba, ui-ux, review, qa, systematic-debugging, property-based-testing and tech-writer skills already cover project ownership and review. External skills should supply domain detail, not duplicate that orchestration. The authorized workspace contains these local companions; their presence is not proof of a standalone fresh clone.

# Findings that change the adoption decision

1. **A current upstream skill can target prerelease dependencies.** The inspected Microsoft CLI package is 0.1.23 and declares Playwright/playwright-core `1.65.0-alpha-2026-10-30`. The project previously tested 1.56.1. Keep its workflow as reference and the existing tested runner; do not install the snapshot as a verified upgrade. The inspected antfu Vitest entry likewise targets a beta. These are observed source versions, not recommendations for the product lockfile.
2. **Performance advice cannot supply authorization.** Vercel's cross-request cache example indexes by user ID alone. Any actual cache here needs an independently reviewed authenticated scope, disclosure/permission version, input revision and invalidation contract. A UI optimization must not weaken backend permission or freshness checks. Shared caching is not needed merely because the example exists.
3. **The interface checklist requires domain exceptions.** It generally keeps submit controls enabled until a request starts, while this billing UI must block unavailable financial prerequisites. Its large-list guidance does not replace bounded server pagination. Locale formatting must retain explicit currency and exact values; it cannot invent FX or select currency from language. Canonical logos cannot be optimized by rewriting SVG coordinates.
4. **Guidelines can fetch another changing instruction source.** Vercel's web-design skill delegates to `web-interface-guidelines/main/command.md`. This research retrieved that file at a commit and recorded its hash. A future wrapper must pin/review that dependency or treat updates as a new research revision.
5. **Agent workflows are not interchangeable.** The inspected Superpowers entry imposes broad invocation, while its execution skill rejects an additional final-fix review pass. That conflicts with this repository's mandatory independent re-review of important changes. Its acknowledgment that user instructions take priority does not remove the need to adapt the workflow. Keep the local planner/review/debugging skills.
6. **A helper can introduce installation and process assumptions.** Anthropic's testing helper starts supplied commands with `shell=True` and pipes server output without consuming it. Its entry says to execute helpers before reading them. Here those files were inspected only. The artifact builder can globally install pnpm, add a broad component stack and delete its output tree; it is excluded from the implementation baseline.
7. **Visual examples can conflict with the approved foundation.** The inspected accessibility modal reference uses translucent, rounded and shadowed presentation. Adopt semantic/focus testing ideas only. UI UX Pro Max has a targeted local-search mode as well as design-system generation; the former may help a concrete UX issue, while system generation/persistence and brand/image scripts are outside this adoption scope. Root inspected the entry files plus selected token/logo scripts; the entire Python/data bundle was not audited or run.
8. **Containers do not prove OS-independent installation and operation.** A multi-stage Dockerfile is an optional artifact strategy. The required baseline still needs portable entry points, no mandatory OS shell/service manager and actual Windows/macOS/Linux support evidence for declared combinations. Developer-tool requirements must remain separate from product installation requirements.

Source paths and hashes for each observation are in [sources.json](sources.json). Script findings are static observations, not reproduced runtime failures or claims of malicious intent.
