# Ownership and boundary

The owner authorizes remediation of F01–F07 on HB-30 and existing PR26. Root owns connection/coverage/receipt orchestration, existing model integration, CLI, runtime tests and documents. An isolated implementer owns a new consumed-semantic validator, its registry/tests and corrections to the separate strict parser/registries. Separate DBA and security reviewers remain read-only. Native cloud connectors, customer data, SaaS hosting and MSP settlement are excluded. Existing MIT/installation clarification is preserved. No merge is inferred.

# Contracts

1. Register an immutable source connection in the independent journal: ID, dataset, coverage namespace, grain, bounded UTC calendar start/end, delivery lag, explicit allowed provider/account/subaccount domain triples and semantic profile. Domains must be an exact subset of active tenant assignments; NULL subaccount requires an explicit NULL assignment, never payer-wide fallback. Reject overlapping connection schedules sharing any economic domain, including differing grains. IDs/names never confer permission. Legacy unspecified deliveries keep their existing identity and exploratory profile.
2. New delivery identity includes connection/dataset/coverage namespace plus checked calendar window. Independent connections have separate revision/current pointers and grains. Continue using global transport revisions only for existing physical batch uniqueness. Corrections replace exactly their connection window. New explicit connections cannot overlap existing legacy windows; reject until operators use a fresh installation/profile or separately reviewed adoption path, rather than double counting retained rows.
3. Validate observed domains against registered expected domains. Missing expected domains require explicit zero-usage attestations (domain, bounded reason and SHA-256 evidence reference) pinned in the descriptor; a declaration never becomes upstream verification. Expose expected windows with missing/late/registered/verified/published/provisional/finalized/known-zero status and as-of times, scoped to current reader membership. Never substitute zero totals for missing coverage. Bound enumeration and fail closed on excess. Existing legacy coverage explicitly reports operator-asserted/unverified expectation.
4. New connections explicitly select a consumed-semantic profile for supported1.2/1.3, pinned by full definition and digest in each batch manifest. The legacy exploratory profile remains available only when explicitly selected and is never promoted to conformance. Validate documented consumed fields, enums, version-specific applicability, exact quantities/costs/prices, strict source formats, provider/host/issuer separation and lossless unique scalar Tags. Derive a normalized semantic context for query from retained source_json and the pinned profile; retain original bytes and existing fact/archive layout without reinterpreting legacy rows. No full-provider conformance certificate is claimed.
5. Scheduler fairness: inspect all bounded directory entries for registered digests, rather than truncate before matching; fail with an explicit inbox bound if the directory exceeds its configured safe bound. Ignore irrelevant/unregistered oversized/bad files without blocking a registered candidate; process one authorized delivery pending publication at a time. No provider API fetch is added.
6. Safe receipt workflow: separate declaration/digest/version/permission/domain admission from consumed semantic validation. Unauthorized/prohibited/unmapped data gets only bounded safe rejection metadata, no raw original. For explicitly admitted but semantically unusable source data, preserve restricted original bytes under an immutable journal intent, track quarantined/replacement-requested/resolved/escalated disposition and bounded replacement authorization. Replacements pin exact predecessor digest, connection/window/version and one-use approval; do not rewrite originals or skip any delivery validation/confirmation. No automatic external messages. Quarantined artifacts participate in backup/restore and retention/hold handling; do not claim all-copy physical erasure.
7. Reject regressing complete-through or unfinalizing a finalized predecessor unless a distinct operator-approved reopening plan pins connection/window/predecessor/new digest and a safe reason. Bind that plan into registration and preserve history. Initial provisional publication remains supported.
