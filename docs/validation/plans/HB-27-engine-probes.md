# HB-27 engine behavior probes

Tracking: Linear ticket [HB-27](https://linear.app/hybrid-billing/issue/HB-27). Owner: Seung Woo Park. Machine: `mac_mini`. Branch `feature/HB-27-physical-data-verification` from main `a68c075`. Design under test: [platform data build design](../../architecture/platform-data-build-design.md).

## Scope

A local, disposable verification stack and probe scripts. No product code, no real accounts, no customer data. Inputs are synthetic values generated by the probes. Credentials are random local values generated into an ignored `.env` file; `.env.example` holds placeholders only, and Compose uses `${VAR:?}` without defaults. Ports are published on `127.0.0.1` only; the ClickHouse `default` user is disabled; SeaweedFS S3 requires credentials; PostgreSQL uses `scram-sha-256`, never `trust`. A scoped `deploy/local/verification/.gitignore` ignores `.env` because the root `.gitignore` is not yet tracked in Git.

## Demo-first data verification follow-up

The owner clarified that the actual FOCUS demo dataset is the first representative data-review and end-to-end fixture baseline. Follow the [demo dataset baseline](HB-27-focus-demo-baseline.md) for artifact provenance, observed provider/service coverage, version compatibility and consumed-column inventory. This supplements the engine probes without changing their synthetic inputs or recorded outcomes. Demo-backed verification and live external collection are separate work within the existing HB-27 scope; this update does not report either as executed.

## Probes

| ID | Question from the design | Method | Expected or recorded |
| --- | --- | --- | --- |
| EP-01 | `sum` over `Decimal(38,S)` near the Decimal128 limit | Insert values whose sum exceeds 38 digits; run `sum` with `decimal_check_overflow` 1 and 0 | Record whether it errors or wraps; design requires an independent bound either way |
| EP-02 | `sum` result type and overflow from Decimal64 inputs | Sum `Decimal(18,6)` values beyond 18 digits | Record result type and correctness |
| EP-03 | Text with more fractional digits than the column scale | Insert `'1.1234567'` into `Decimal(18,6)` from CSV and from `s3()` | Record truncate, round or error |
| EP-04 | Load defaults turning NULL or empty into zero | Matrix: Nullable and non-Nullable money columns × CSV and Parquet × NULL and empty values, under default settings and under the design's locked settings | Record each cell; design expects locked settings to give NULL (Nullable) or a load error (non-Nullable), never zero |
| EP-05 | Parquet with a missing consumed column | Load with `input_format_parquet_allow_missing_columns` default and 0 | Default: silently filled; 0: error |
| EP-06 | `join_use_nulls` | Left join with no match under 0 and 1 | 0: default values; 1: NULL |
| EP-07 | Row policy fail-closed and cross-tenant isolation | First read the effective `access_control_improvements` values; reader with no matching policy, with and without `throw_on_unmatched_row_policies` (and `users_without_row_policies_can_read_rows` if present); reader with a tenant-A policy queries tenant-B rows | Record each; design expects error without a policy and zero tenant-B rows |
| EP-08 | Reader cannot bypass | Reader calls `s3()`, `url()`, `remote()`, `file()`, `INSERT INTO FUNCTION`, `ALTER`, `ATTACH`/`MOVE PARTITION`, reads `system.named_collections`, and tries to change locked settings (`join_use_nulls`, input format settings, `serialize_query_plan`) | Denied in every case |
| EP-09 | Synchronous lightweight delete | Delete rows of a release attempt with `lightweight_deletes_sync`; count immediately | Zero remaining rows |
| EP-10 | Parquet export of Decimal and Nullable | `INSERT INTO FUNCTION s3(...) FORMAT Parquet` then read schema with pyarrow | DECIMAL logical type with declared precision and scale; nullable preserved |
| EP-11 | Conditional create, versioning and object lock on SeaweedFS | `PutObject` with `If-None-Match: *` twice on the same key; enable bucket versioning and object lock and try overwrite and delete | Second write rejected (412); overwrite keeps the prior version; locked object cannot be deleted. Anything unsupported is recorded and the control journal store is marked not certified |
| EP-12 | `s3()` against SeaweedFS with named collection | Read a CSV and a Parquet object through a named collection; provoke an access error | Works; no credential appears in `system.query_log`, `system.text_log` or error text |
| EP-13 | PostgreSQL RLS with a non-owner role | Verify the role is neither owner, superuser nor `BYPASSRLS`; `FORCE ROW LEVEL SECURITY`; scope via `SET LOCAL`; query with no scope, after `COMMIT` on the same session, and after the variable was set once in the session (`current_setting(..., true)` returns `''`) | Zero rows in every case, never all rows; no scope leak across transactions |

## Out of scope (recorded as NOT_RUN)

- Conditional create in customer-operated S3 services: part of later store certification.
- Money types in real provider Parquet exports and which providers export FOCUS 1.3: need provider samples, not available here.
- Production, HA, performance and capacity behavior.

## Exit criteria

Each probe has an observed outcome (`CONFIRMS`, `CONTRADICTS` or `NOT_RUN`) recorded in the run summary with image digests, run ID and timestamps. Results that contradict the design are listed as design changes for the physical schema step. A probe that cannot run is recorded as NOT_RUN with the reason; nothing is reported as passed without an actual run.
