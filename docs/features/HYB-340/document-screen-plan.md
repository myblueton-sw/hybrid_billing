# Service and recovery boundaries

Use strict bounded parsers for actual command envelopes, context/header/rows, history, retained basis/events, advice and preparation observation. Match request IDs, target, digest, mode, revision, current session/workspace and receipt type. A malformed successful mutation response is an unknown effect. Clean refusal is recognized only from the established status/code/request envelope without an operation; never infer no effect from a later refusal after an earlier unknown outcome.

Freeze packet, target/document/digest, rationale, revision and HTTP idempotency identity before dispatch. Block duplicate sends synchronously. Keep attempts keyed to actual user/workspace/CSRF session identity and retain them across navigation/locale changes. Selection/refresh invalidates advice, not pending/unknown attempts. A confirmed success survives failed refresh. Explicit reauthentication invalidates advice without automatic retry. Existing server reauthentication updates the session timestamp without rotating CSRF; verify this in the browser journey. New login uses server history rather than claiming browser memory persists.

Independent client-state plan review passed with these explicit requirements: use one session-owned controller across responsive detail copies; hidden copies must not dispatch or own separate locks. Complete all pages atomically with matching request/digest/revision/header, unique ordered rows, bounded page count and no cursor cycles. Partial context never enables packet review. Keep unresolved attempts visible after selection changes and preserve their original operation references after later refusals. Disable fresh-key recovery while any attempt for the same owned preparation key is pending. New-login discovery is evidence for recovery, not reconstruction of a lost original HTTP envelope or rationale.

Same-key resend always retains the exact original envelope and historical intent. Fresh-key preparation recovery is a separate explicit action after current inspection, with the same owned preparation key, document and proposal digest, and a new expected revision from the latest read. Freeze the recovery rationale/revision/new HTTP key once. Never generate a replacement preparation key merely because a response is unknown. Original ownership is actor-bound, so recovery must be unavailable to another actor even when they can inspect history; the server independently enforces this. Matching ledger observation is not a recorded receipt. Missing observation is not proof of no earlier effect. No external submission, posting or issuance action exists.

# Resolutions of Claude contract questions

The packet uses exact case-sensitive Go field names from financialDocumentPacket and its line type; client builders must preserve them. IDs use the existing 1–128 ASCII letter/digit/dot/underscore/colon/hyphen contract. Generate collision-resistant client IDs once; a conflict does not justify replacing an unknown intent. Packet decimals use canonical nonnegative strings: zero is 0, no plus/exponent/leading zeros/trailing fractional zeros; quantity is strictly positive and scale is limited by ERP context. Declared totals must equal exact canonical sums. Preserve user-entered text for correction rather than silently rounding.

The 4096-byte packet ceiling does not guarantee retained-record admission. Generic prerequisite_failed cannot safely be described as a proven size failure; show that current prerequisites or record limits were not satisfied, retain the draft/intent and request a fresh check. Do not invent a size-specific server code. Advice's generic blocked code must not be mislabeled as a proven hold or as the viewer's denied permission. Context proposal_permission closes first-document permission discovery; it is not packet readiness.

Fresh-key preparation recovery uses a newly read global result_revision, while same-key resend keeps its original revision. Propose/confirm/revoke use exact same-key resend and retained-history inspection; no automatic fresh-key replay is offered. The one explicitly selected configured combination supplies each line's product/tax identifiers. No unsupported general catalog or default tax amount is inferred.
