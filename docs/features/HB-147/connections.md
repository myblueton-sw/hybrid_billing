# Scope and ownership

[HB-147](https://linear.app/hybrid-billing/issue/HB-147/bind-s01-to-protected-retained-collection-connection-metadata) follows merged HB-145 at main `eb4da1a`. Root owns PM, contract, frontend, QA and integration. An isolated implementer may own only the backend projection, dispatcher and new backend tests. A separate read-only architecture/security reviewer checks design and actual changes. Material layout composition and rendered comparison use the required Claude CLI ui-designer. No owner FIX is transferred or created.

Default S01 `/connections` gains bounded inspection of retained `focus_import` connection registrations. The explicit `service=local` and existing object-ID legacy flow remain separate. Preserve four tabs: connections, capabilities, security and diagnostics. Registered coverage, installed source-version support, external authentication, diagnostics and billing eligibility are different facts. Existing public/synthetic retained data may have zero attributable registered connections even when legacy deliveries exist; do not synthesize registrations from deliveries or infer upstream readiness.

No configuration/credentials, diagnostics, revocation, upload/import/reset/migration, publication, financial commands, customer data, real accounts or deployment. Development interfaces use portable Python/Node/browser APIs; actual evidence remains host-specific.

# Producer and authorization

Reuse `OverviewServer` and fixed server actor with `collection.access(actor,'query')` and its current query authority transaction, delivering the response inside both guards. Preserve Host/Origin/FetchSite/header/method/body/concurrency/no-store checks. This is trusted-local operator reading, not production multi-user authentication.

Reuse the reviewed `configuration`, `members_for` and `authorized_connections` helpers. Only connections whose entire registered domain set resolves through current active configuration and is inside current permitted membership may contribute records, counts, search or public pins. Exclude foreign, mixed/unowned, duplicate-domain or ambiguous connections. The verified readiness/ownership guards may internally read control configuration and domain values; do not serialize them into DTOs, public pins, logs or review state. Do not load original bodies or warehouse facts, or expose global journal projections, raw configuration, account/domain values, object keys, paths, URLs, credentials or capability payloads. Explicit current registered metadata is the only source; never reconstruct a connection from a delivery or source account intersection.

For an owned connection, validate each exported scalar and registered interval before serialization; inconsistent owned metadata fails closed. Use actual supported source-version registry, day/month grain, UTC interval and producer limits. Reuse pure `connections.calendar()` to check midnight/month boundaries and its3660-window limit, without invoking definition/add/registration or reconstructing capability payloads. Do not call a registration command while reading. Do not treat an empty owned map as proof of no connections in excluded scopes.

# Closed GET contract

Fixed `/api/focus-connections` accepts only `view`, `q`, `after`, `snapshot`, `permission_revision`. Views are connections/capabilities/security/diagnostics; default connections. Prefix `q` is0..128 lowercase token characters `[a-z0-9:_-]`. `after` is canonical integer0..10000; positive after requires both lowercase SHA256 pins; one pin without the other rejects. Page25 maximum; result count above10000 rejects. No actor/company/tenant/URL/body inputs or duplicate query keys. Security/diagnostics are unsupported and return total=null, no records and next_after=null; positive after rejects.

Exact envelope keys: schema=1, profile='retained-focus-connections-v1', read_only=true, financial_authority=false, commands='unconnected', view, selection={q,after}, audience=tenant|company, member_count, auth_scope, permission_revision, snapshot, observed_at, total, next_after, capabilities, records. `member_count` positive safe integer <=10000. Counts/page offsets are safe integers0..10000; total may be null only for unsupported views. Capabilities exact keys: connections='fully-owned-registrations-only', capability_evidence='registration-only', provider_authentication='unconnected', diagnostics='unconnected'.

Exact record keys: id (canonical scoped SHA256), connection (producer token1..64), focus_version (actual registry token), grain=day|month, window_start, window_end, registered_domains, semantic_profile, allowed_lateness_seconds, replacement_limit. Registered domains are only an explicit fully owned registration count, not source-discovered or collected account count. `semantic_profile` is focus-consumed-v1|exploratory-query-only; it is not a conformance certificate. Numeric record values are canonical decimal strings: registered_domains1..10000, allowed_lateness_seconds0..604800, replacement_limit1..10. All fields are required; none is nullable. Dates are strict valid UTC ISO timestamps, start inclusive/end exclusive, with actual fractional precision retained. Owned invalid records reject the response. IDs are unique and bind the profile and producer connection identity. Sort by connection token deterministically; search matches only visible connection or canonical id prefixes.

All public hashes use SHA256 of the existing canonical JSON encoder with these exact allowlists. Record `id` hashes `{profile,source,connection}` using the verified configuration's non-secret source identity and producer connection token. `auth_scope` hashes `{profile,source,actor,audience,members}` with sorted authorized opaque tenant IDs only. `permission_revision` hashes `{auth_scope,policies}` where policies is a sorted list of `{member,revision}`; revision is only each current authorized member policy's validated positive integer revision, rendered as a decimal string. No full membership property or policy object is hashed. Missing/invalid policy revision fails closed. `snapshot` hashes `{profile,permission_revision,view,q,capabilities,total,records}` with the entire filtered, sorted, whitelisted result (not only the page). After and volatile observed_at are excluded so a pinned selection can page. No raw configuration/domain/account/capability payload, hidden policy field or foreign/unowned fact enters public hashes. Changing hidden registration fields/capability payloads or foreign facts alone must leave all public pins unchanged; visible record changes invalidate snapshot, while authorized member or policy-revision changes invalidate authorization/permission pins. Current guard checks still run on every request.

On stale evidence/permission pins return409 and require refresh. Missing producer404 remains unconnected;403 denied,409 changed evidence, malformed data and503 source failure clear prior evidence. Response size and streamed consumer body maximum2MiB; closed keys/types, fatal UTF8, strict dates/counts/pagination/duplicate IDs, fixed same-origin URL, GET-only and redirect rejection.

# Screen and review identity

Preserve canonical shell, assets/local fonts, four tabs and stable S01 IDs. The connection list shows registered ID, source version/profile, registered interval and domain count; selected detail explains lateness/replacement registration policy separately. Capabilities shows registration-only evidence and explicitly unknown external supplier/product support. Security and diagnostics have honest unavailable states with refresh and no fake command buttons or secret fields. Links to S03 use only an exact visible connection prefix, then destination reauthorization; do not pass client actor/tenant claims.

Use prefix filter/apply/clear, refresh, pinned paging and selected detail with keyboard entry/Escape/close-focus return. Body/control/table16px, h2>=20px, neutral square geometry and full-width layout; UTC/IDs/numbers remain LTR in Arabic. No financial values or invented last-success/expiry statuses. Changing tab/filter/page/requested scope, permission or failure synchronously masks old counts/records/detail; abort and monotonic request identity reject late results. Browser Back restores URL selection, not old authority. No persistent DTO cache, runtime fixture switch or automatic owner review. Report current view/query/auth/snapshot/selected record identity in value-free revision evidence; no raw registration body or transient request ID in acceptance identity.

This binds existing screen behavior, not a new provider connector or full S01 configuration workflow. External layout references already established by the adjacent receipt screen are the official Cloudscape table-view and split-panel patterns; consult their actual current contents before material composition, adopting hierarchy only. Native-language/practitioner approval remains separate.
