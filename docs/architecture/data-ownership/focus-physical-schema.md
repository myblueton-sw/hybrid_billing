# First FOCUS path physical storage

Tracking: [HB-27](https://linear.app/hybrid-billing/issue/HB-27). Owner: Seung Woo Park. Machine: `mac_mini`. Root is sole writer; independent DBA/security review is required. Baseline: main `9a5bbb5`, including PR 22. This is a physical design specification, not executable DDL, a migration, accepted production numeric policy or runtime certification.

Inputs: [build design](../platform-data-build-design.md), [logical schema](logical-data-schema.md), [evidence schema](evidence-detail-schema.md), [numeric contract](../../contracts/billing/claim-and-numeric.md), [engine observations](../../validation/reports/20261022T035254Z-bac19a/summary.md) and [official demo inventory](../../validation/reports/HB-27-focus-demo-inventory/summary.md). The demo was inspected first; its unsupported 1.0 version and incomplete fields prevent using it to certify 1.2/1.3 ingestion. [Consumed mappings](focus-consumed-columns.md) define supported-version semantics; [lifecycle procedures](focus-lifecycle-protocols.md) define three implementation prerequisites.

## Scope, types and ownership

First path: connection → original receipt/quarantine → validated input manifest → immutable cost/usage release → separately confirmed per-attribution publication → authorized query/export/rebuild. PostgreSQL is authoritative; ClickHouse is reproducible evidence, and S3 stores exact originals/exports/control journal. ChargeLine, Claim, pricing, monthly-close and issuance tables remain governed by their existing contracts and require their own physical design; an input release never authorizes billing.

All tenant tables below carry `installation_id uuid NOT NULL, workspace_id uuid NOT NULL`, abbreviated `S`. Every PK, FK and tenant uniqueness predicate includes S; IDs alone cannot join workspaces. Attribution/customer/source account IDs are not tenant authorization. UUIDs identify records, never correction or commit order. Revisions/attempts/epochs use positive bigint with checked exhaustion (never wrap); byte sizes/counts nonnegative bigint; digests are 32-byte SHA-256 bytea with length check; instants use timestamptz and UTC output; intervals check start < end. Original timezone/calendar revisions stay in the manifest. Bounded JSONB describes versioned manifests, not untyped money or a substitute for relationship constraints.

Every mutable state row has revision bigint, recorded_at timestamptz, command_id uuid and actor_ref uuid. Every idempotent command has unique `(S, command_namespace, request_key)` plus canonical input digest; identical replay returns the existing result after current authorization, changed input conflicts. Financial/numeric values travel as exact decimal strings; PostgreSQL `numeric` without typmod is proposed for small control sums only after lexical/profile validation, with NaN/Infinity forbidden. No implicit DB rounding selects business policy.

PK notation lists columns after S. All references carry S and the exact target PK/revision. Unless described as immutable, updates are restricted to reviewed owner commands and expected revision.

`source_revision` identifies the provider revision, not one payload. Each original/conflicting/quarantine-replacement payload has a separate immutable receipt digest and predecessor link; authorized replacement consumes the re_request record without overwriting the quarantined payload or changing provider revision identity.

Publication `attribution_id` denotes a stable customer/economic attribution scope, distinct from its mapping revision. Remapping cannot create a new current-pointer domain to bypass predecessor CAS. Split/merge/reassignment requires an explicit transition that locks the union of old/new stable scopes, retires predecessor pointers and installs the replacement set atomically with exact coverage checks; ambiguous overlap holds all affected scopes.

Deferred FKs handle creation cycles: insert release then attempt and current_attempt in one transaction; create domain and operation with deferred references, preserving at most one active operation. State transition triggers/owner procedures must prevent mutation of sealed manifests, immutable decisions and history. Retry allowed SQLSTATE serialization/deadlock errors with bounded policy; never silently retry a changed business input.

RLS: enable and FORCE row-level security on every tenant table; application roles neither owner, superuser nor BYPASSRLS. Transaction-local installation/workspace context derives from authenticated authorization; absent/empty context denies, including reused pooled sessions. Use `NULLIF(current_setting(..., true), '')` before UUID parsing. RLS is defense in depth; composite keys/FKs and server-derived query scope remain required. Application users cannot choose arbitrary GUC scope or issue SQL; the trusted API owns context. Migration/maintenance roles are separate and inaccessible to users.

## ClickHouse first cost/usage fact

Proposed table `hb.focus_cost_usage`, immutable MergeTree. Grain is one observed source record occurrence in one release attempt; preserve legitimate equal rows. Fact locator `(receipt_id, source_row_ordinal)` identifies occurrence, not economic uniqueness. Source economic identity/multiplicity comes from the activated provider profile; FOCUS alone supplies no universal unique row key.

| Column group | Proposed physical type / rule |
| --- | --- |
| Scope | `installation_id UUID`, `workspace_id UUID`, `attribution_id UUID`, `lifecycle_domain_id UUID`; all NOT NULL and assigned by trusted mapping |
| Identity | `release_id UUID`, `attempt UInt64`, `receipt_id UUID`, `source_row_ordinal UInt64`, `writer_epoch UInt64`, `writer_generation UInt64`; PG positive signed bounds also enforced by loader |
| Versions | `manifest_digest FixedString(32)`, `schema_revision UInt64`, `mapping_revision UInt64`, `numeric_profile_revision UInt64`, `source_revision_id UUID`, `declared_focus_version LowCardinality(String)` |
| Time | billing/charge start/end `DateTime64(9, 'UTC')`; checked original source timezone and exact timestamps retained in original/manifest; reject source precision outside supported profile instead of truncating |
| Dimensions | Nullable String for each mapped lexical dimension, including currency and unit; low-cardinality optimization only after measurement; Tags preserved as validated JSON text plus disclosure profile |
| Measures | Each consumed cost/quantity/unit price `Nullable(Decimal(P_column,S_column))`; P/S specialized from activated per-column numeric profile, no universal default |
| Missing provenance | Per consumed field small reason code: present, source_null, absent_by_version, not_applicable, invalid; field registry/version fixes meaning. Invalid never enters an eligible release |

Proposed `PARTITION BY toYYYYMM(charge_period_start)`, `ORDER BY (installation_id, workspace_id, attribution_id, toDate(charge_period_start), release_id, attempt, receipt_id, source_row_ordinal)`. These are hypotheses pending measured pruning, row width and retention rewrite costs. Do not partition per release or tenant. Mixed-retention month partitions require verified scoped rewrites and lifecycle coordination, never blanket partition deletion. No ReplacingMergeTree, mutation-based publication, projections, TTL deletion or financial division/round/cast in queries.

The tested loader profile changes to `input_format_csv_empty_as_default=1`, `input_format_null_as_default=0`, `input_format_parquet_allow_missing_columns=0`, `join_use_nulls=1`, `serialize_query_plan=0`, with server-side immutable constraints for loader/readers. The old probe profile deliberately remains unchanged for reproducibility. Candidate configuration must receive its own implementation diff review and lock/bypass tests. Requiredness is a prepublication field/applicability gate, not non-Nullable storage. Missing mandatory consumed fields quarantine/hold affected scope; no blank becomes zero. Row policies restrict exact scope; reader credentials cannot mutate or call external/table functions or access collection secrets.

## Numeric profile activation

For every numeric column record P, S, largest absolute submitted coefficient, allowed signs, max rows per release and aggregate, unit/currency/basis, actual `sum` return type/width, intermediate growth, and Python arithmetic capacity. Validate source lexical value/scale before normalization and before ClickHouse; Float money quarantines. For input bound C and n_max require `n_max*C <= min(10^P_sum-1, 2^(W_sum-1)-1)` for every allowed aggregation domain. Use absolute bounds, never cancellation; profile must cover multi-release query sums too. Exceeding a bound fails before load/query, never wraps. P<=38 is a representation ceiling, not an approved policy. Unknown profile values block DDL specialization and activation.

Python exact integer coefficient/scale arithmetic or explicitly sized Decimal context independently recomputes every total used for pricing. Bound context precision for all intermediates, trap unexpected rounding/inexact, and match exact control tuples/counts/NULL counts. EP-01 proves Decimal128 sums can wrap; EP-03 proves excess scale truncation; neither DB option nor loaded-value comparison replaces source validation. FOCUS permits exponent notation while the internal financial API contract rejects it: the intake adapter parses finite external decimal syntax exactly with bounded input/exponent, validates original magnitude/scale and emits canonical fixed-point strings; it does not relax the internal API contract. Unsupported syntax/profile fails explicitly.

## Publication and readers

1. Validate originals and source-derived controls independently; link exact receipts and revisions in immutable manifest. Allocate release and current attempt in PG. Claim mutation operation under the lifecycle protocol.
2. Load only through the fenced coordinator; every row is tagged with scope/release/attempt. A retry first proves earlier writers drained, synchronously deletes obsolete attempt rows and verifies zero; timeout alone cannot authorize retry.
3. Stop attempt writes and prove terminal/drained state; verify scoped counts, exact controls, missing reasons and header/applicability checks. Mark eligible attributions ready, others held. Independent confirmation binds exact manifest and attribution set.
4. Acquire every affected lifecycle-domain row in canonical order, then publication_scope rows in canonical order. Hold them through current policy/authority/dependency validation and PG commit. Domain state must allow publication; confirmed attempt must be immutable and drained. Compare predecessor release+scope revision, check source correction order, and atomically update pointer, increment scope revision, seal release, register dependency pins, append decision and export/journal outbox. A failed scope CAS changes no pointers/pins/decisions. Incomparable provider revisions require explicit review.
5. Export only the exact sealed attempt through the coordinator; verify Parquet DECIMAL/NULL types, digest and control tuples before marking rebuild eligible. Missing export remains explicit pending/unrebuildable state, not silent success.
6. For each request resolve authorized attribution pointers in PG, acquire lifecycle-coordinated pins for exact release/attempt set, then query CH with those explicit pairs AND scope/attribution predicates. Current access/field/recipient checks also occur before output. No CH latest selector or cross-customer aggregate before disclosure filtering. Pins remain until terminal/cancel/drain evidence.

## Implementation exit gates

Design review acceptance is distinct from executable acceptance. Before migrations/loaders: choose and independently approve exact provider numeric/revision/multiplicity profiles; select supported 1.2/1.3 fixture or reviewed adapter; specialize DDL and constraints; review migration/recovery/role grants. Before product use: run tenant FK/RLS negatives, duplicate/correction races, stale writer/publication races, three lifecycle protocol scenarios, scoped NULL/overflow/excess-scale tests, export/rebuild controls and actual query/capacity measurements. No >100M/day performance claim follows from this draft. OTLP billing usage, full financial schemas, production/HA, live connectors and production migration are outside this first-path design.
