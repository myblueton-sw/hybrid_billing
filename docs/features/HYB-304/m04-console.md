# Strict read client

The dedicated types, parser and factory cover seven bounded list methods and five canonical details. They reuse actual transport/CSRF/no-store/auth-loss handling and issue one GET per invocation. Every caller supplies expected workspace explicitly; canonical detail IDs, scope audience and captured query are checked after the asynchronous response. Decimal-string counts/versions remain strings; sums/comparisons use BigInt, never Number coercion. Current command preconditions reject contradictory flags while preserving legitimate reductions under trust hold and declaration repair despite currently ineligible metadata. Unknown totals/unevaluated summaries are not zero. Full selectors/restrictions retain explicit closed unions, named literal all, permitted actions, exclusive upper periods and the producer's1000-field maximum.

Independent review reproduced Go versus JavaScript Unicode case/whitespace differences. The backend now adds required search_input to all seven list bodies as exact decoded request-q correlation metadata, or empty when omitted/history. The client compares it to the captured serialized q without attempting to reproduce Go Unicode tables. Normalized query.q remains the applied-filter/cursor scope. Equivalent normalized requests may continue the same signed cursor while the exact input echo changes; no additional raw-input policy is added to the cursor. The normalized string's defensive output bound allows Go simple-case UTF8 expansion after its original64-byte input validation. Never render search_input as a substitute for applied query.q.

Synthetic samples come from actual authenticated HTTP handlers, then the Console parser/factory consumes all12 shapes. Additional cases cover sigma, dotted I, NEL/FEFF whitespace, Korean, Arabic, simple-case byte expansion and equivalent normalized continuation. Initial absent methods are labelled new-API absence, not a preexisting semantic bug. Actual Unicode and contradictory-affordance fail-before records are distinct. Source review, executions and UI readiness are reported separately.

# Ordered state and recovery migration for design review

1. Introduce a scoped query-state owner for accounts, credentials and pending-collection metadata with separate normalized filters, current page, canonical selected ID and bounded cursor trails. Owner, organization, audience, scope and declaration history pickers keep independent pages, not accumulated catalogs. An empty scan-limited page with continuation remains incomplete. Browser back/forward restores the exact scope/selection; request tickets reject stale responses after scope, query, target or session changes.
2. Replace global user-only issue recovery with a dedicated context provider inside the authenticated ServiceContext lifetime, wrapping service children without adding DOM and owning a stable-client and canonical session scope. Capture user/workspace/CSRF only in memory, never logs or persistence. Same client/session scope preserves entries across locale/view remounts; changed client/session/workspace starts isolated recovery and releases obsolete listeners/guards. Subscribe to actual authentication loss and deliberate leave to invalidate late callbacks and release retained secret references. Add explicit dispose/unsubscribe for onDeliberateLeave and beforeunload registrations. Do not release recovery merely because an M04 component unmounts during same-scope navigation. Create/dispose the active store within the provider effect, publish only a store matching the current immutable client/scope and suppress publication after synchronous authentication loss. Effect cleanup disposes old listeners and outstanding callbacks; React development StrictMode effect cleanup/setup must create a fresh live store, not reuse a disposed one. While scope is changing, recovery consumers receive no old store. Listener construction must be render-pure. One-time secret collection must share the same in-flight request across StrictMode effect setup/cleanup/setup, without an automatic second consume; its exact ownership is a separate design gate before reveal wiring.
3. Replace population reconciliation with exact known-credential observations. Missing from any page is unknown. Only a post-issuance canonical read of the same service/credential with authoritative revoked/expired/returned-once evidence may retire that issued entry. A never_collected observation alone can reflect temporary issuer-authority loss and must preserve its reference. Older reads, mismatched IDs, failed requests and page absence cannot remove an issued entry. Initial known-ID requests remain bounded by locally recorded attempts, never a server-wide population. Store no returned secret in the recovery model. Keep references until actual collection success or terminal evidence; opening the reveal view alone is not successful collection. Preserve the one-time reveal and unstored mark semantics, explicit discard and same-key uncertain replay.
4. Freeze the entire submitted command fingerprint: command, canonical target, rationale, metadata fields, exact catalog/declaration version, expected revision and attempt. Unknown retries reuse it byte-for-byte even after a read refresh or edited picker. Do not silently renew the attempt or scope. Authoritative refusal and explicit discard permit a new draft; a known success is resolved canonically even when outside the current page.
5. Bind create/declare to actual bounded metadata pickers and current canonical selection details. Retain missing/ineligible historical selections visibly and require intentional repair; no automatic replacement. Empty configured catalog is an actionable unavailable state. Purpose/org/responsible owner/selected audience-scope restrictions are complete producer fields. Display effective setting defaults/ranges and preserve unrelated installation semantics across language changes.
6. Connect the real M04 list/detail/actions and HYB-333 recovery regions. Existing reveal/command components may be split by responsibility, with no invented full-page arrays or page-dependent command admission. Credential, selected service and global pending-collection scopes are independent. Count certainty, current observations and fixed query reference remain explicit.

Permitted files: the dedicated service query modules, service-accounts scoped state/recovery/form/components/copy/styles/tests, narrow existing shared helpers only with established consumers and affected field/register/operations/evidence records. Root is sole writer. Independent reviewer must assess the state/session and complete command fingerprint design before those changes, then inspect actual diff. No change to auth grants, server pickup authority, financial policy or protected runtime/data.
