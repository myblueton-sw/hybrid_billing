# Scope and composition

HB-144 covers P01–P07 and C01–C03. The original planning inputs and hashes are in screens.json. Root owns these leaves and integration. Dedicated components implement installation plan/diagnostics/support/access, extension registration/events, recovery stages, retention and decision states, release evidence, isolated learning, licence entitlements, customer monthly overview, disclosed documents and public inquiries. Only small form, evidence and table presentation primitives are shared. Canonical tabs and owner review controls remain in the shell.

Each view exposes its domain fields and unknown source values. In-memory drafts validate required inputs, present a review summary, focus the first invalid field and clear input. No producer API is invented or called. Input review is explicitly separate from authority, signature, integrity or execution verification. There is no financial/authentication/installer/restore/delete/send operation or fabricated assistant output. Customer views accept no internal payload and expose no cost, margin, private note, recognition journal or other customer's data. Public documents do not imply payment; inquiry resolution does not imply refund.

P06 is an isolated learning-plan surface with a scenario selection, fixture version, integer seed, virtual clock and mock-fault plan. No mock engine or operational DEMO identity is claimed. P07 separates entitlement evidence from the frontend's actual build-generated original licence notices; local package search and fixed same-origin original-notice links are the only notice interactions. Marketplace entitlement linkage remains deferred.

# Integration and review identity

The shared dispatcher separates four domains and canonical presentation audiences. Presentation selection is not authentication. Prelogin canonical/legacy routes now reach unconnected identity forms rather than defaulting to an administrator preview. Public portal paths use their own shell; dual-audience leaves remain structurally restricted. Existing S03 local integration is preserved separately.

Every input edit increments a value-free scoped revision in the dispatcher. Review state combines leaf fragments and stable item IDs so wrapper effects cannot erase domain-specific review scope. It never reads form values, credentials or content. Context changes reset the revision, fragments and local children. Owner confirmation is never created by implementation or QA.

The extracted ScreenTabLabel responsibility preserves prior financial tab wording. Existing17 leaf files, foundation assets and styles are unchanged; shared routing/body dispatch affects only the requested32 plus the explicit prelogin projection. The global build fingerprint changes, but this is not an owner reacceptance or automatic FIX. Prior fixed evidence remains intact.
