# Reviewed public contract

Both inspection commands and result_evidence.advice add one bounded JSON application_context. Mutation receipts and command inputs remain unchanged. The shared producer validates all retained chains and both reverse indexes before projecting kind (initial/replacement), position (not_started/current/historical), predecessor identity/digest/report revision/processing receipt, and current reserved head identity/state (none/unknown/recorded).

An unstarted replacement describes the currently observed prospective target; it is not a retained predecessor relationship yet. An owned replacement names its immutable predecessor. A current head may remain unknown. Historical ancestors retain completed receipts, but an unknown newer head does not prove the actual ledger was replaced. Conflicting associations refuse. Cost authorization precedes protected lookup.

Strict consumers accept only the closed shape and validate position, application status, predecessor receipt and current head coherence. Inspection/advice must carry identical context and server revision before a frozen action review. Context does not grant permission. Worst-case public output admission includes a complete maximum-width context. Fresh command dispatch checks the frozen server revision under the domain lock; identical replay remains a historical outcome subject to current authority checks.

Root initially questioned interrupted-operation revision invalidation. Independent reviewer traced actual command execution: fresh unknown operations advance Server.counter through changed(), while Next() only formats a revision. A public two-request regression passed without any command source correction. No ineffective Next() mutation was introduced.

# Design and terminology

Root inspected the official [GOV.UK check answers pattern](https://design-system.service.gov.uk/patterns/check-answers/). Adopt grouped readable effect/target summaries before submission, but reject fixed content width, branding and edit links for immutable history. No third-party assets or code are imported.

Claude inspected existing recovery-review.png, recovered.png, proposal-review-ar-1440.png and proposal-review-ko-390.png. The actual report is /private/tmp/hyb341-replacement-design.txt. It prescribed a position statement directly below the result heading, grouped internal application detail, collapsed technical references and a readable frozen action summary. Existing full-width layout, local Plex fonts, neutral separators and visible focus remain authoritative. Mobile stacks summary labels and values; identifiers and hashes are directionally isolated. Apply/recovery names distinguish replacement from initial application.

Independent terminology review corrected three preliminary designer assumptions: unknown reserved head does not establish live application, a historical ancestor with an unknown successor does not prove completed replacement, and a stranded predecessor cannot be promised recovery merely by retrying. Copy now states uncertainty explicitly. Internal processing record hash replaces payment-receipt terminology. Recovery uses the original actor/current permissions/evidence and is distinct from starting another operation. The screen and action-review boundaries preserve no ERP transmission/posting/final financial approval. Role-based review is not native-language acceptance.

No position label is added to unloaded history rows: the existing list contract does not provide application context, so the scoped detail alone shows verified position. The UI never derives current/historical status from report revision or client-side sorting.
