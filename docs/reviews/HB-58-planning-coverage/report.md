Classifications:

- **Missing journey:** a dedicated connected flow is absent from the current book/drafts inspected, even if a detailed local specification exists.
- **Partial:** relevant fields, examples or controls exist, but the required decision/state sequence is not demonstrated.
- **Inconsistent companion:** an older local spec contradicts a newer canonical decision; this is not proof of a runtime defect.
- **Deferred/conditional:** preserve an explicit owner deferral or selected-path condition; do not present it as an unconditional launch requirement.

“Additional” below means made explicit beyond the HB-55 summary, not a newly invented product requirement. “Expanded” refines an already recorded gap. Suggested ordering concerns planning work only.

# Proposed planning order and completion standard

1. **Administration and relationship design:** ADM-01–04/07/08, with method-neutral identity/recovery states and accurate product-profile navigation. Write module 02/04/11 planning revisions with stable screen IDs and cross-links.
2. **Operational work and settings:** OPS-01–04/07/08; connect calendar, work inbox, notification settings, installation/support and audit/report detail. Preserve existing financial screens and distinguish job status from business completion.
3. **Recovery and lifecycle planning:** ADM-05/06 and OPS-05/06/09; govern sensitive configuration, final settlement, migration, restore and retention. Related finance/security design requires independent review.
4. **Cross-document reconciliation:** DOC-01–03 and OPS-10 policy placement, while keeping the already recorded financial/VMware and disclosure backlog visible. These may run before dependent module design where a contradiction would otherwise propagate.

Each planning revision must identify the user/role, entry point, scope, fields, current-to-new effect, approval requirement, normal/empty/loading/blocked/stale/revoked/partial/unknown result and return path. Map each action to the canonical command or explicitly unresolved contract; do not invent an endpoint. Include at least one normal and one blocked/recovery walkthrough and a trace from original clause to active screen/state. Planning acceptance does not check off runtime tests. No new full-book freeze is justified until the chosen scope is traced and explicitly accepted; preserve frozen v10 until an accepted replacement identifies its actual scope.
