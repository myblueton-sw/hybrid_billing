# Temporal contract

Keep immutable received revisions. A server-provisioned delivery profile explicitly assigns provider/account/subaccount domains to existing tenants. Each registered complete delivery has an exact digest, row count, mapping version, source revision and nonoverlapping window. Window granularity is day or month, never mixed for overlapping intervals. A monthly cumulative refresh replaces the previous current revision of that same month, rather than adding it. Daily deliveries accumulate distinct daily windows. Register/retry/collect is durable and idempotent; equal economic rows remain distinct. Late corrections replace only the exact window after independent manifest confirmation, preserving all previous revisions. Incomplete/unknown deliveries never publish. Source-specific completeness is an explicit trusted local registration assertion, not inferred from file existence. Only configured mapping registry versions are accepted.

Queries select fixed current-window pointers and generate a snapshot digest; subsequent pages require that digest. Day/month grouping uses declared tenant timezone and charge-start attribution; intervals spanning a day are labelled source resolution, with no fabricated proration. Currency and quantity units stay separate and missing values stay missing. Mixed daily and monthly cumulative scope is rejected rather than double counted. Existing one-snapshot CLI remains compatible.

# Lifecycle contract

Provision explicit revisioned tenant policies (basis received_at or window_end, hot days, total days, backup horizon, grace and accountable approval). Do not invent legal defaults. The original clock is immutable across replay/copy/recall. Archive each tenant slice to private typed Parquet, verify bytes/hash, decoded row digest/count and dimensional totals before catalog transition. Recall verifies the same controls before use. Retention preview freezes an exact manifest and reports holds, dependencies, shared original references, active operations and backups. Execution requires a distinct approval of that digest and rechecks all restrictions under the same coordinator lock and PostgreSQL gate/tenant locks. Active deletion and backup residue are distinct.

Use a trusted single-host coordinator lock for local CLI operations plus a durable independent append-only restriction journal outside the PostgreSQL restore domain. Journal entries and current head are fsynced and mirrored to immutable object storage; every operation checks continuity and current head. An operation intent survives process/session loss and blocks reads/writes/restore while any storage effect is unknown. No lease expiry or new token is a fencing proof. Normal success proves terminal effects before clearing intent. No automatic takeover of an unknown operation. Restrictive intents win before any deletion boundary; after durable deletion authorization a new hold reports too-late instead of a preservation promise. Shared originals are deleted only after all affected tenant slices are eligible; minimal duplicate/tombstone metadata survives for the configured replay/backup horizon. A local filesystem journal is independent of DB rollback, not host disaster redundancy.

Backup captures metadata plus referenced immutable objects/Parquet and dependency manifests. Restore is maintenance-only, closed to normal traffic, refuses unknown dispatched operations, verifies current independent control head, applies all latest tombstones/holds/revocations before reopening and verifies retained data. Restoring an old database cannot clear a pending intent or latest tombstone. Missing journal/head/object, policy outage, mismatched hash and incomplete restore fail closed. External downloaded files and unmanaged replicas are reported outside the local controlled inventory; no universal all-copy deletion claim.

## Design refinement: stable scope and bounded selection

A window is source + exact UTC day/month interval; the single registered source covers all configured tenant domains. Each source chooses one granularity. Calendar is explicitly UTC for intake windows; reporting grouping uses each tenant timezone. Economic delivery revision is per window; existing global batch source_revision is only an internal monotonically allocated storage sequence. Only exact window replacement is allowed. Registered source domains are provider/account/subaccount triples derived from pinned tenant assignments and reject ambiguous owners. Every row must match an allowed triple/currency; day deliveries require charge intervals contained in the day, month deliveries require billing intervals contained in the month (charge dates can lag billing periods and are reported honestly). Registration pins exact input bytes, row count, domain multiplicity, mapping digest and trusted completeness assertion. It does not establish provider-side completeness.

The query snapshot contains sorted exact window/delivery/batch/tenant-slice descriptors plus current policy/audience digest, filters and grouping. Cursor includes window, batch and ordinal, never ordinal alone. Bound the full selected result to 10000 rows and all six additive absolute-coefficient sums below 10^38. Reject overflow or oversized selections explicitly; no silent truncation. Monthly cumulative data cannot be mixed with overlapping day windows. Former revisions are retained for history and lineage but omitted from current-window sums. Registration and publication compare the exact current predecessor for that window.

The independent local control journal is a coordinator-only authority, not caller supplied configuration. Readers retain existing role-bound PG/CH scopes and get only authorized catalog projections. Every trusted CLI operation uses the same single-host lock; PostgreSQL policy rows and source gate serialize with existing revocations. This is not a multi-host worker deployment. Unknown dispatched operations have no automatic retry/takeover/restore path; an operator must supply actual route fencing and terminal-effect reconciliation through a separately reviewed recovery procedure. Do not add unsafe lease-based automatic recovery to claim availability.

## Review resolutions and explicit authority

All windows of this registered source have UTC boundaries and include the entire configured economic-domain allowlist; no arbitrary domain subset is a separate overlapping source. Intersecting distinct registered windows are rejected even before publication. Exact-window corrections use increasing per-window revision and predecessor CAS. Header-only CSV is accepted only as an explicitly registered complete empty correction, with zero rows and the exact digest. Month registrations pin complete-through/as-of and finalized versus provisional state; no final-month completeness is inferred for a partial month.

Retention is whole tenant/batch slice, never an unsafe partial partition. Policies choose first receipt of the window or source window end as origin. Origins are immutable and inherited by corrections; every retained revision has catalog/dependency entries. New references/holds and deletion use the same locks. Archive reads are verified private coordinator reads under current reader authority; corrupt/missing bytes deny. Expired current scope produces explicit unavailable/expired error for tenant/company queries, never an apparently complete subtotal. Queries can select an unaffected explicit interval.

The journal has an installation UUID, monotonic sequence, previous hash and fsynced current head independent of restored PG. Initial activation imports all existing retained batch slices into the controlled inventory. New input before a monotonically advancing source rejection floor is held even if old duplicate records have been compacted; no new-receipt clock reset. This implementation initially retains minimal control identities and exposes no automatic compaction. A missing activated journal cannot be silently reinitialized when the PG activation/checkpoint exists.

| Unknown action or reader/importer destructive call | none | Reject before any effect |

The trusted local operator/approver choices are CLI scenario identities, not production authentication. Maintenance admin credentials are confined to explicit maintenance commands; reader roles gain no deletion grants. All trusted CLI entry points, including old importer operations, check lifecycle activation/current controls and share the coordinator lock. Direct administrative SQL and copied credentials are outside the trusted single-host execution contract.

Deletion tracks tombstone, query-visible row absence, mutation completion, inactive ClickHouse parts, object versions and managed backup copies separately. No lightweight/mutation row absence is labelled physical erasure. Unknown inventory is UNVERIFIED and prevents policy-complete status. Reconcile checks actual inactive parts and store versions; backup horizon expiration requires actual removal/read-back. Shared originals stay until all tenant and dependency/hold/backup obligations clear. Outside local inventory, downloaded copies and uncontrolled replicas remain declared residuals. Restore only opens after current journal continuity/installation/head and restrictions are verified; unknown dispatched work has no automatic recovery. Backup and restore retain all pinned configs, schemas, manifests and typed slice artifacts; reconstruction is not new billing execution.


## Implemented review refinements

The runtime journal initially retains full shared source/configuration/recovery evidence. Per-slice deletion inventories that residual and never claims policy-complete removal. Whole-source retirement has a distinct approved manifest, mirrored pending deny anchor, committed PG purge with independent read-back, generated-binding cleanup and exact local file inventory, followed by a minimal compact terminal anchor. It excludes physical media/WAL erasure and caller-owned input/downloaded copies from its completion scope. Unknown or temporary local artifacts block cleanup. Backup deadlines inherit original policy origins and enforce restore cutoffs even before pruning. Retirement approval covers the fixed business inventory and its deterministic preparation/approval control-entry closure; a new business effect invalidates it.
