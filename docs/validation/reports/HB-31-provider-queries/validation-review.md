# Verdict

Tracking: HB-31. The owner's follow-up asks whether the tested criteria are suitable as validation checks for future collection, after OCI/VMware query verification. **PASS for reusing the bounded invariants below; UNVERIFIED for complete supplier-feed or financial acceptance.** No production validation code is changed by this review. Independent DBA/change review confirms these distinctions by source inspection; the sample query and pure-profile executions are separate evidence.

Passing a fixed sample is insufficient to approve arbitrary future data. The reusable criterion is that the declared source contract, authorized scope, complete delivery and persisted/queryable values agree. Counts such as1123 rows,39 represented services and the particular provider labels are fixture assertions, not production allowlists or expected billing totals.

# Required boundaries before a future supplier-feed acceptance claim

1. **Bind a reviewed source profile.** Record supplier/export/dataset identity, actual declared version, capabilities, scope and schema. Choose a supported strict semantic profile explicitly. Currently consumed profiles exist for1.2/1.3; FOCUS1.0 samples and explicit exploratory paths must retain their limited classification until a1.0 source contract is separately implemented/reviewed. Do not guess an OCI/VMware version or upgrade a sample by changing its version label.
2. **Prove transport compatibility.** AWS-style DOUBLE and GCP-style nested extension reproductions are rejected by the current Parquet importer. Outer gzip/ZIP and supplier multipart manifests are not raw intake contracts. Internal Parquet compression is supported within expansion bounds and must not be confused with an outer compressed delivery. Any adapter needs explicit exact-value, original-preservation and part-assembly rules; disabling these guards is not a validated fix.
3. **Establish delivery completeness independently.** Pin all expected parts, digests, account/calendar coverage and authoritative control evidence for the complete window. Current describe/row-count/domain digests are derived from the supplied file and can be self-consistent while upstream rows are missing. Cumulative month-to-date deliveries must replace the same whole monthly window as a newer revision; they must not be summed as independent daily deltas. The current same-window revision/pointer checks support replacement, but do not authenticate a supplier's assertion that every part is present.
4. **Keep validation stages distinguishable.** Parsing, consumed-field validation, storage verification, authorized publication and actual bill/invoice reconciliation establish different facts. Re-run the independent lexical comparison on approved real supplier-shaped samples before expanding a compatibility claim. Financial acceptance additionally requires external bill/contract/invoice evidence, which this task did not receive. Passing the39-service sample or the16 synthetic profile probes cannot satisfy that missing evidence.
